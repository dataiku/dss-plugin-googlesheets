- Use this recipe to export multiple DSS datasets to separate tabs in one Google Sheets document with a shared append or overwrite mode. Prefer one multisheet writer instead of multiple Sync recipes, a Stack recipe, or custom native recipe logic when no data transformation is needed.
- Bind source datasets to `input_role` and one DSS managed folder to `output_role`. The folder is required for Flow execution despite being optional in the descriptor; no files are written to it. Ask which folder to use unless specified, and create it first if needed.
- For `auth_type="single-sign-on"`, select an accessible `oauth_credentials` preset from the `single-sign-on` parameter set. For `auth_type="preset-service-account"`, select `preset_credentials_service_account` from the `service-account` parameter set.
- The authenticated account needs edit access to the spreadsheet; share it with the service-account email when using a service account. If authentication setup is incomplete, ask the user to finish it in DSS. Configure legacy `credentials` in DSS settings rather than requesting private keys in the conversation.
- Set `doc_id` to the existing spreadsheet ID between `/d/` and `/edit` in its Google Sheets URL. This recipe does not create spreadsheets; `document_name` and `folder_id` are unused.
- To choose tab names, set `tabs_mapping` to objects such as `{"input_dataset":"PROJECT.dataset","output_sheet_name":"Sales"}`. Use the exact fully qualified input dataset name and an exact, nonempty tab name, rather than a numeric `gid`.
- An input without a mapping uses its dataset name without the project prefix as the tab name. Confirm ambiguous destinations with the user and use distinct tab names for separate exports, including inputs from different projects with the same dataset name. Missing tabs can be created during execution.
- `write_mode="append"` adds rows without adding headers. `write_mode="overwrite"` clears each target tab and writes input column names followed by the rows. This mode applies to every input.
- When all target tabs are confirmed new, use `write_mode="overwrite"` to include headers unless the user explicitly requests append. If any target tab already exists, clarify ambiguous write intent before overwriting; do not clear existing tabs just to add headers to new ones.
